    Check your own account

    Run the open-source scanner in AWS CloudShell, where you're already signed in, then open the result here. It takes about five minutes and nothing is installed on your computer.

    1. Open AWS CloudShell

      Sign in to the AWS account you want to check, then open CloudShell. Your user needs read access to the services checked; SecurityAudit or ReadOnlyAccess covers it.

      Open CloudShell

    2. Run the scan

      Paste these two commands. The scan only reads settings and takes two to four minutes across all regions.

      pip3 install --user git+https://github.com/Judewakim/SOC2-Compliance-Workbook.git
~/.local/bin/soc2kit scan --out soc2-evidence

    3. Download the results

      In CloudShell choose Actions, then Download file, and enter soc2-evidence/report.json. The full evidence pack for your auditor is the .zip in the same folder.

    4. Open it here

    Running it on a schedule or from another account? Use the read-only role template and --role-arn, as described in the README.

    What's in the evidence pack

    Auditors test evidence, not dashboards. Every pass and fail comes with the API response it was based on, a timestamp, and a hash that shows nobody edited it afterwards.

    • report.html

      Readable report: score, every failure with the resource and the fix, and coverage by criterion.

    • workbook.xlsx

      The SOC 2 workbook. Automated results plus 22 procedural controls with owner, status and evidence columns.

    • evidence/*.json

      The raw AWS API responses behind each check, per region, with capture times.

    • manifest.json

      A SHA-256 hash of every file, so the pack can be shown to be unaltered.

    • report.json

      Machine-readable results for a compliance platform, a ticketing system, or this page.

    How it works

    Evidence, not opinions

    Every check has an explicit pass rule. If a check can't run, it says so instead of passing. If there's nothing to check, it's marked not applicable rather than compliant.

    Read-only by design

    The role is generated from the checks themselves: 35 read actions, no data reads, no writes. Tests fail the build if the policy drifts or a write permission appears.

    Honest about scope

    Most of SOC 2 is people and process. The workbook lists the 22 procedural controls automation can't see, so nothing is mistaken for complete.

    Python, boto3, AWS STS, IAM, CloudFormation, Terraform, Jinja2, openpyxl, pytest with moto, GitHub Actions.
