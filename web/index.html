    Scan your own account

    Run the open-source scanner in AWS CloudShell, where you're already signed in, then open the result on this page. About five minutes, nothing to install on your computer.

    1. Open AWS CloudShell

      Sign in to the account you want to check and open CloudShell. Your user needs read access; the SecurityAudit or ReadOnlyAccess policy is enough.

      Open CloudShell

    2. Install and run the scanner

      The first command installs it, the second scans every enabled region. It only reads settings and takes two to four minutes.

      python3 -m venv ~/soc2kit && ~/soc2kit/bin/pip install -q git+https://github.com/Judewakim/SOC2-Compliance-Workbook.git
~/soc2kit/bin/soc2kit scan --out soc2-evidence

    3. Download the report

      In CloudShell choose Actions, then Download file, and enter soc2-evidence/report.json. The .zip in the same folder is the full evidence pack for your auditor.

    4. Open it here

    Scanning from your laptop, CI or another account? Deploy the read-only role and pass --role-arn; the README has the steps.

    What goes in the binder

    Each scan produces one folder you can hand to an auditor or attach to your compliance platform.

    report.htmlThe readable report: every failure with the affected resource and the fix, plus coverage by criterion.
    workbook.xlsxThe SOC 2 workbook. Automated results, plus the 22 procedural controls automation can't see, with owner and status columns.
    evidence/The raw AWS API responses behind each result, per region, with the time they were captured.
    manifest.jsonA SHA-256 hash of every file, so you can show the evidence wasn't edited after the scan.
    report.jsonThe results in a machine-readable form, for scripts, ticketing or this page.

    How it's built

    A pass has to be earned
    Each check has an explicit rule. If it can't run, it's marked not tested. If there's nothing to check, it's marked not applicable. Neither one counts as a pass.
    Read-only, and provably so
    The IAM policy is generated from the checks: 36 read actions, no writes, no data reads. The build fails if the policy drifts or a write permission appears.
    Honest about the other 70%
    Most of SOC 2 is process: access reviews, training, vendor checks. The workbook lists those 22 controls so nobody mistakes a clean scan for a finished audit.

    Built with Python, boto3, AWS STS and IAM, CloudFormation, Terraform, Jinja2, openpyxl, pytest with moto, and GitHub Actions.
